# UI 规范 — 最新版本：极简 Apple 风格

视觉主参考：`../assets/iphone-ui-minimal.png`；上一版较复杂的 UI 不再优先采用。要求使用 **真实 SwiftUI 控件、数据绑定与系统交互** 复刻体验，而不是把 PNG 充当软件屏幕。

## 视觉调性

- 白色、超浅灰、雾面玻璃，局部系统蓝色强调，状态绿色仅用于已被验证的真实连接。
- SF 系统字体（支持动态字体），一级标题醒目，二级文字中性灰，不把文本挤成小字。
- 大圆角（卡片约 20–28pt，按钮约 14–20pt），超轻阴影，模糊层用于少量重要容器。
- 每屏有限个关键操作；视觉留白充足；不用插画或大图消耗相簿空间。
- 兼容深色模式、VoiceOver、减少动态效果与高对比度。

## iPhone：首页“相册”

从顶部到底部：

1. `照片传输` 大标题，一行真实 `已连接 MacBook · USB` 或 `未连接`。
2. 一张轻毛玻璃设备卡：设备名、USB 图标/状态、可选真实容量；主按钮 `开始导出`；次按钮 `导入到 iPhone`。
3. `相册` 标题 + 查看全部，标准照片式相簿行：**真实封面**、相簿名、照片数量、箭头，最多三行在首屏可见，滚动更多。需要虚拟化 + 缓存缩略图，禁止加载所有全尺寸图片。
4. 低调信息行：`保留原相簿顺序`，可以显示 `0001 / 0002 / 0003` 的真实先后预览；如未通过 G1 则显示“顺序读取待验证”，不要显示绿色成功图标。
5. 底部原生标签：`相册 / 传输 / 恢复 / 设置`。不要冗长浮动快捷菜单。

## iPhone：相簿详情

- 顶部标准返回 + 相簿名 + 照片总数，3 列或 4 列方形图片网格，体验类似系统“照片”App，相邻图片间 2–3pt 间距。
- **展示顺序必须来自实际检测的相簿顺序**；禁止 `creationDate` 自动排序更改用户手动顺序。
- 点击图片可查看原图，显示原名 / 资源类型 / 显示顺序索引；默认不提供拖拽重新排序（A 方案）。
- 页面底部固定一个明确的 `导出此相簿` 按钮；批量选择为辅助功能。

## 传输页

- 已传文件数、总数、实时 MB/s、USB 设备状态、清晰的细线进度条。
- 一次只强调最重要状态，主要控制为“暂停 / 继续 / 取消”，未完成校验不得显示已完成。
- 失败的图片以文本报告和可重试项展现，不需要冗长的性能监控仪表盘。

## 恢复页

- 选择 Mac 备份相簿，显示文件总数、通过 hash 校验数量和已存 manifest 的顺序预览。
- 主动作 `恢复到 iPhone`，可输入目标相簿名，已有成员冲突采取非破坏性确认策略。
- 恢复完成显示 `文件完整性` 与 `自建相簿顺序` 两项独立的实际验收状态；不应只有一个笼统完成动画。

## 设置页

默认尽量少：
- 原图传输（只读固定开）、5 秒排序时间步长（默认固定 5 秒）、自动校验 SHA-256（默认开且不可绕过）。
- 文件命名预设（按序号 + 原始文件名），Mac 存储目录、深浅色模式跟随系统、日志导出。
- 高级设置中的“修改 iPhone 照片库显示时间”必须**默认关闭**，有清晰警告并记录原值。

## Mac 原生 App

- 一体窗口，左侧 Sidebar：iPhone 设备、相簿、历史；中间为照片缩略图/表格切换；顶端简洁连接状态、导入和导出动作；底部真正的速度与进度。
- 原生 NSOpenPanel 选目标保存路径；窗口尺寸适配 2018 MacBook，CPU/RAM 消耗要克制。
- 设计仍是极简：背景淡灰、列表白色、局部毛玻璃、大圆角、细分隔线；不要照搬移动端密集卡片。

## 可接受实现细节

- 使用 SwiftUI 原生 List、NavigationStack、TabView、Material、PhotosUI 适当辅助，但照片库原始顺序与原始数据读取仍需 PhotoKit 管理。
- 动画 0.15–0.3 秒级别且可关闭；不以持续动态效果掩盖卡顿。
- 空相簿、受限权限、无 USB、空间不足、iCloud 原件未就绪、缺失 manifest 都要有优雅空状态与真实解决操作。
