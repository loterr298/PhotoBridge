## 文件一致性与元数据

- HEIC/JPEG/PNG：逐资源 SHA-256 校验（备份阶段）；像素尺寸、色彩元数据、相机型号、镜头、EXIF 拍摄参数、GPS、MakerNotes 的可读字段逐项对比。
- ProRAW/DNG：真实 RAW bytes，不替换成预览；DNG 厂商 metadata 保留。
- Live Photo：静态主资源和 paired MOV 不遗漏，关联正确；资源组在 manifest 用同一 ordinal。
- 编辑过的照片：明确记录原图与当前已编辑渲染版本；系统不可完整导出的资源必须报告，不伪装原样恢复。
- iCloud Optimize Storage：请求真实原件、显示网络依赖；如果下载失败，则该照片不能标记成功。
- Mac 时间：ordinal 1、2、3 的逻辑时间为 +0、+5、+10 秒；跨 999 张仍保持准确；时区统一 UTC。
- 原始文件 bytes 必须保持；如果只有文件系统时间改变，则照片原始 SHA-256 不变。PhotoKit 往返后单独读回进行核验（不假设必然 byte-for-byte 一致）。
- 同名 `IMG_0001.JPG` 两个不同资产、跨相簿共享资源、相簿名冲突不发生覆盖或错配。

## 大批量性能与健壮性

- 数据规模：100、1,000、10,000 张；另有大文件、Live Photo 和一部分 DNG 的混合集。
- 记录：端到端总耗时、实测 MB/s、峰值 RAM / CPU、最大磁盘暂存、读取/写入错误数和实际 USB 连接情况。
- 插拔数据线在 10%、50%、90% 阶段发生：恢复后不产生“成功但 hash 不同”的文件；完成数和序号不漂移。
- 空间不足、文件权限不足、目标磁盘拔出、原图 iCloud 下载失败、没有照片访问权限、部分照片被删、系统锁屏：全部有明确失败/恢复路径。
- 导出失败 1 张时必须可定位缺失序号，不能将下一张图片替换到原位置。
- 重复运行/重复导入不会未经确认覆盖或删掉用户资源。

## UI 真值要求

- 无设备时只能显示“未连接”而不是“已连接”。
- 没有真实吞吐测量，不能显示随机速度数字。
- 相簿只显示真实照片缩略图和真实照片数；示意占位若用于预览要标注开发状态。
- “顺序验证成功”必须来源于实际的源/目标索引比对；失败时展示差异位置与原因。
- 动态字体/VoiceOver/暗色模式/窄屏布局无明显遮挡。
